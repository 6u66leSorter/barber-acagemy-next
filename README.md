# MADCAP Barber Academy

Учебное MAX Mini App для барбер-академии. Приложение даёт ученику возможность вести учебный дневник и сдавать работы, преподавателю — проверять их, а администратору — просматривать учебные данные. Гость может смотреть публичное портфолио без доступа к контактной информации.

> Статус версии: ветка `refactor/nest-react`. Перед сдачей зафиксируйте конкретный commit hash или тег из этой ветки и не изменяйте его после дедлайна.

## Доступ в MAX

Для проверки в MAX Mini App должен быть опубликован по HTTPS, а его публичный URL должен быть указан в карточке MAX-бота. Токен бота хранится только на сервере в `MAX_BOT_TOKEN` и никогда не добавляется в репозиторий.

Docker-проверка ниже воспроизводит локальную версию, но не заменяет доступное мини-приложение в MAX: MAX передаёт подписанные данные запуска только при открытии приложения из мессенджера.

## Основной пользовательский сценарий

1. Ученик открывает Mini App из MAX и проходит регистрацию.
2. Ученик создаёт домашнюю работу: указывает урок, формат, название и текст либо вложение.
3. Преподаватель видит назначенных учеников и ожидающие проверки работы, добавляет оценку и комментарий, одобряет работу или отправляет её на доработку.
4. Ученик получает уведомление, при необходимости отправляет доработку и продолжает обучение.
5. Одобренные работы могут отображаться в публичном портфолио без телефонов, MAX ID и приватной переписки.

## Состав и архитектура

| Компонент | Технологии | Назначение |
| --- | --- | --- |
| `frontend/` | React, TypeScript, Vite | интерфейс Mini App и клиент API |
| `backend/` | NestJS, TypeScript | аутентификация MAX, роли, учебные сценарии и REST API |
| SQLite | `better-sqlite3` | локальное хранение пользователей, ролей, работ, оценок и уведомлений |
| `docker/` | Nginx | раздача production-сборки frontend и проксирование `/api` в backend |

Схема слоёв и текущий план переноса находятся в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [docs/REWRITE_PLAN.md](docs/REWRITE_PLAN.md).

## Быстрый запуск через Docker

Требуется Docker Desktop 4+ с Docker Compose v2. Локальный режим без настоящего MAX-токена запускается одной командой:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up --build
```

После сборки откройте http://localhost:8080. Внутри контейнеров запускаются все необходимые компоненты: Nest API, SQLite и Nginx с React-сборкой.

Для запуска в строгом режиме MAX создайте `.env` из шаблона и заполните токен только на машине/сервере, где запускается API:

```bash
cp .env.example .env
# укажите MAX_BOT_TOKEN и оставьте MAX_WEBAPP_AUTH=strict
docker compose up --build
```

## Параметры окружения

| Переменная | Обязательность | Значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `MAX_BOT_TOKEN` | обязательна для MAX | — | секрет бота для проверки подписи init data |
| `MAX_WEBAPP_AUTH` | да | `strict` | `strict` — только подписанный запуск MAX; `off` — лишь локальная проверка |
| `MAX_INIT_DATA_MAX_AGE_SEC` | нет | `3600` | допустимый возраст MAX init data в секундах |
| `API_PORT` | нет | `8787` | внутренний порт Nest API |
| `DATABASE_PATH` | нет | `/app/data/barber.db` в Docker | путь к SQLite-файлу |
| `CORS_ORIGINS` | нет | `http://localhost:8080` | разрешённый origin frontend |
| `CHAT_ENABLED` | нет | `true` | включает чат |
| `APP_NOTIFICATIONS_RETENTION_DAYS` | нет | `90` | срок хранения уведомлений |

Шаблоны без секретов: [.env.example](.env.example) и [backend/.env.example](backend/.env.example). Не создавайте и не коммитьте файлы `.env` с реальными значениями.

## Порты и зависимости

| Порт | Компонент | Доступ |
| --- | --- | --- |
| `8080` | Nginx + React | браузер и локальная проверка |
| `8787` | Nest API | только внутренняя сеть Compose; frontend обращается через `/api` |

Зафиксированные версии JavaScript-зависимостей находятся в [package-lock.json](package-lock.json). Без Docker требуется Node.js 20.19+ или 22.12+ и команда `npm ci` из корня проекта.

## Внешние сервисы и интеграции

| Сервис | Назначение | Что нужно проверяющему |
| --- | --- | --- |
| MAX | открытие Mini App и передача подписанных данных пользователя | публичный HTTPS-адрес Mini App в настройках бота |
| MAX Bot API | серверная проверка токена и init data | `MAX_BOT_TOKEN` только в окружении API |
| Docker Hub | загрузка базовых образов `node` и `nginx` при первой сборке | доступ к интернету при первой сборке |

В Docker не воспроизводится сам MAX, поскольку это внешний мессенджер. Для локальной проверки используется явный файл `docker-compose.local.yml`.

## Данные и тестовые данные

В production SQLite хранится в Docker volume `barber_data`; его не следует удалять при обычной остановке контейнеров. В базе могут находиться персональные данные, поэтому файл БД, вложения, резервные копии и `.env` исключены из Git.

После запуска локального режима подготовьте обезличенные тестовые данные:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml exec api node backend/scripts/seed-demo.mjs
```

Скрипт создаёт идемпотентно три тестовые роли и одну учебную работу:

| Роль | MAX ID для API-проверки |
| --- | --- |
| ученик | `1000000001` |
| преподаватель | `1000000002` |
| администратор | `1000000003` |

Скрипт не очищает существующие данные. Для совершенно чистого локального запуска удалите только тестовый Docker volume:

```bash
docker compose down -v
```

Эта команда удаляет локальную SQLite-базу в Docker volume; не используйте её с production-данными.

## Сценарий проверки

1. Запустите локальные контейнеры командой из раздела «Быстрый запуск через Docker».
2. Выполните `seed-demo.mjs` из раздела «Данные и тестовые данные».
3. Откройте http://localhost:8080 — локальный режим использует тестового ученика `1000000001`.
4. Убедитесь, что API доступен: http://localhost:8080/api/health должен вернуть `{"ok":true,"service":"barber-academy-api"}`.
5. Проверьте учебные данные ученика:

   ```bash
   curl 'http://localhost:8080/api/student/homeworks?max_user_id=1000000001' \
     -H 'X-Max-User-Id: 1000000001'
   ```

6. Проверьте очередь преподавателя, заменив ID на `1000000002`, и список учеников через `/api/teacher/students`.
7. Проверьте административный список через `/api/admin/students` с ID `1000000003`.

Ожидаемое поведение: ученик видит работу со статусом `pending`; преподаватель видит назначенного ученика; административные маршруты доступны только роли `admin`; гостевое портфолио отвечает на `/api/guest/portfolio-students` без MAX-аутентификации.

## Остановка и повторный запуск

Остановить контейнеры, сохранив базу:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml down
```

Повторный запуск использует тот же volume:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up
```

## Известные ограничения

- MAX Mini App требует отдельного публичного HTTPS-размещения и настройки URL в карточке бота; локальный Docker не делает приложение доступным с телефона.
- Ветка `refactor/nest-react` содержит продолжающийся перенос экранов из исходного приложения: API и архитектурные модули уже разделены, но перед финальной сдачей нужно завершить интерфейсные сценарии и провести проверку реального MAX-запуска.
- Docker Desktop должен быть запущен; первая сборка зависит от загрузки базовых образов.
