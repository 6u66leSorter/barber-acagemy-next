# Рабочий журнал

Здесь остаются только краткие итоги завершённых существенных задач. Это не стенограмма чата и не список мелких действий.

## Формат записи

### YYYY-MM-DD — Название задачи

- **Цель:** что требовалось получить.
- **Сделано:** какие части проекта изменены или проверены.
- **Проверка:** какие команды, тесты или сценарии выполнены.
- **Вывод:** что важно помнить в следующей работе.
- **Следующий шаг:** если он определён.

## Записи

Новые записи добавляются после завершения существенной задачи или по явной команде пользователя сохранить итоги.

### 2026-09-17 — Переход на MAX-only

- **Цель:** удалить прежние платформенные интеграции и оставить только MAX.
- **Сделано:** frontend и API переведены на прямой `max_user_id` и подписанные MAX init data; удалены старые клиенты, авторизация, конфигурация, зависимости и внешние уведомления. Локальный браузерный предпросмотр и публичный гостевой раздел сохранены.
- **Проверка:** поиск старых платформенных идентификаторов, `npm run lint`, `npm run build` и локальная проверка API на чистой временной базе.
- **Вывод:** существующую локальную БД старого формата не переносить — для MAX-only версии нужна новая база. Реальный запуск внутри MAX дополнительно проверить с токеном и доменом владельца.

### 2026-09-14 — Единый демонстрационный интерфейс дневника

- **Цель:** собрать и довести до единого стиля страницы ученика, преподавателя, администратора и гостя.

Добавлены правило снятия преподавателей у барбера и конфиденциальная обратная связь ученика.
- **Проверка:** пройдены роли и основные вкладки в локальном Chromium/Edge; проверены ширины 320 и 390 px, API прав отзывов, `npm run lint` и production `npm run build`.

### 2026-09-08 — Кабинет преподавателя: очередь проверки

- **Цель:** дать преподавателю профиль, отдельную очередь новых домашних заданий и список закреплённых учеников.
- **Сделано:** добавлены вкладки «Профиль», «Проверить», «Ученики» и «Уведомления»; очередь показывает только учеников с ДЗ в статусе ожидания проверки и ведёт к их портфолио. В карточке ученика преподаватель видит обучение, средний балл, метро, описание и работы, но не номер телефона.
- **Проверка:** `npm run lint` и `npm run build` прошли успешно.
- **Вывод:** телефон исключён и из интерфейса, и из ответов API преподавателя; он остаётся доступен только в сценариях ученика и администратора.
- **Следующий шаг:** настроить демонстрационного преподавателя в локальном API и пройти вручную сценарий «Проверить → ученик → оценка/комментарий».

### 2026-09-08 — Заполненный предпросмотр преподавателя

- **Цель:** сделать кабинет преподавателя наглядным для обсуждения дизайна.

- **Вывод:** демонстрационные имена, фото и записи существуют только в локальной БД и режиме предпросмотра; в production используются реальные данные аккаунтов.

### 2026-09-08 — Комментарии внутри домашнего задания

- **Цель:** дать преподавателю возможность оставлять неограниченное число дополнительных комментариев к любой работе закреплённого ученика, а ученику — отвечать в том же контексте.
- **Сделано:** добавлена таблица `homework_comments`, API добавления комментариев с проверкой доступа и уведомлениями, а также лента комментариев и формы отправки в карточке ДЗ для обеих ролей.
- **Проверка:** преподавательский комментарий и ответ ученика сохранены и прочитаны через API; визуально проверены на странице ДЗ. `npm run lint` и `npm run build` прошли успешно.
- **Вывод:** комментарии отделены от оценки/решения по работе, поэтому преподаватель может возвращаться к уже принятому ДЗ и продолжать обратную связь.

### 2026-09-07 — Демонстрационный дизайн страницы ученика

- **Цель:** показать заполненный профиль ученика в светлой премиальной стилистике с сохранением фирменного золотого акцента.

Добавлены сгенерированные иллюстративные портреты исключительно для локального режима `?preview=1`; реальные аккаунты используют собственные аватары.
- **Проверка:** `npm run lint` и `npm run build` прошли успешно; страница вручную проверена в локальном предпросмотре.
- **Вывод:** фотографии из демо не являются фотографиями пользователей и не должны подменять их в production.
- **Следующий шаг:** после утверждения ученической страницы проработать интерфейсы преподавателя, администратора и гостя.
