# План переноса монолита

Перенос выполняется по слоям, чтобы на каждом этапе сохранялась рабочая сборка.

1. Каркас workspace, NestJS, React, MAX auth, health и session — выполнено.
2. SQLite schema/repositories и миграция старой базы.
3. Пользователи, регистрация, роли и профиль.
4. Ученик: домашние задания, фотографии, исправления, рейтинг и обратная связь.
5. Преподаватель: очередь проверки, ученики, оценки, комментарии и чат.
6. Администратор: модерация учеников/преподавателей, назначения, профили, аудит.
7. Гость и публичное портфолио.
8. React-страницы, формы, загрузки, темы, адаптивность и MAX Bridge.
9. Деморежим для проверки экспертами.
10. Docker, production-конфигурация, smoke/e2e проверки и перенос в `main`.

Старый runtime сохраняется в родительской ветке до завершения переноса. Реальные даты коммитов отражают фактическую работу; коммиты разделяются по законченным этапам, а не создаются задним числом.
