# Пользовательские сценарии production/MAX

## Условия проверки

Production-версия открывается только из MAX Mini App и использует подписанный `initData`. Для полноценной проверки нужны:

- публичный HTTPS-домен;
- URL приложения в карточке MAX-бота;
- один и тот же `MAX_BOT_TOKEN` в боте и окружении API;
- `NODE_ENV=production`;
- `MAX_WEBAPP_AUTH=strict`;
- постоянные SQLite и uploads на volume или примонтированном серверном каталоге;
- резервная копия БД и uploads перед обновлением.

Локальный заголовок `X-Max-User-Id` в production не является способом входа и должен получать `401` без корректного `X-Max-Init-Data`.

## Первый запуск

1. Пользователь открывает Mini App из карточки бота в MAX.
2. Frontend получает init data из окружения MAX и передаёт его API.
3. API проверяет подпись, обязательные параметры, возраст и отсутствие дубликатов.
4. При корректной подписи API использует MAX user ID как внешний идентификатор.
5. Если учебного профиля ещё нет, приложение показывает onboarding.

Ожидаемые ошибки:

| Ситуация | Результат |
| --- | --- |
| заголовок init data отсутствует | `401`, понятное сообщение о запуске из MAX |
| подпись неверна | `401`, сессия не создаётся |
| init data устарели | `401`, предложение закрыть и заново открыть Mini App |
| повторяется защищённый параметр | `401` |
| API недоступен | интерфейс ошибки с возможностью повторить запрос |

## Пользователь без учебной роли

### Регистрация ученика

1. Выбрать «Стать учеником».
2. Заполнить имя, телефон, число уроков и метро.
3. Исправить подсвеченные ошибки валидации, если они есть.
4. Отправить форму один раз.
5. Получить состояние `moderation` и инструкцию ожидать решения администратора.

Повторная регистрация не должна создавать второй профиль. До назначения роли пользователь не должен видеть чужие работы, чат или административные страницы.

### Заявка преподавателя

1. Выбрать «Стать преподавателем».
2. Заполнить имя и телефон.
3. Отправить заявку.
4. Увидеть состояние ожидания модерации.
5. После одобрения администратором закрыть и заново открыть Mini App либо обновить сессию.

## Ученик

### Повседневный сценарий

1. Открыть главную учебную сводку.
2. Создать работу, указав урок, название, описание и файл.
3. Дождаться уведомления о проверке.
4. Открыть оценку, отзыв и комментарии преподавателя.
5. При статусе «На доработке» описать изменения и приложить исправленный файл.
6. После одобрения проверить работу в публичном портфолио.
7. Общаться только с назначенными преподавателями.

### Профиль и обратная связь

1. Изменить публичное описание — оно обновляется сразу.
2. Загрузить аватар допустимого формата.
3. Отправить имя, телефон или метро на модерацию.
4. Получить результат рассмотрения через интерфейс/уведомление.
5. Отправить приватную обратную связь об академии или преподавателе.
6. После 5, 10 и 15 одобренных работ увидеть приглашение оставить обратную связь, без повторного приглашения для того же рубежа.

## Преподаватель

1. Открыть сводку и увидеть всех назначенных учеников.
2. Найти ученика строкой поиска.
3. Открыть историю его работ.
4. Просмотреть защищённые файлы.
5. Добавить комментарий.
6. Одобрить работу с оценкой 1–5 и отзывом либо отправить на доработку.
7. Убедиться, что ученик получил уведомление.
8. Ответить ученику в приватном учебном чате.

Преподаватель не должен видеть учеников, которые ему не назначены, их диалоги, телефоны, MAX ID или username.

## Администратор

1. Открыть сводку академии.
2. Найти ученика и открыть полную административную карточку.
3. Создать или отредактировать ученика.
4. Изменить его учебный статус.
5. Создать преподавателя или управлять его ролью.
6. Назначить преподавателя ученику либо снять назначение.
7. Одобрить или отклонить заявку преподавателя.
8. Одобрить или отклонить правку профиля ученика с комментарием.
9. Просмотреть приватную обратную связь.
10. Проверить журнал административных действий.

Все административные API должны возвращать `403` ученику и преподавателю. Потенциально опасные действия в интерфейсе требуют подтверждения.

## Гость

Публичное портфолио доступно без init data. Гость может искать учеников и смотреть имя, описание, метро, преподавателей, рейтинг и одобренные работы активного ученика.

Публичные ответы не должны содержать:

- телефон;
- MAX ID и username;
- pending/revision/rejected работы;
- приватные комментарии и обратную связь;
- чат и уведомления;
- файлы неактивных учеников.

## Файлы и ошибки сети

- Поддерживаемые пользовательские форматы: JPEG, PNG, WebP, MP4, MOV и PDF.
- Сервер проверяет фактическую сигнатуру и лимит, а не доверяет одному MIME от браузера.
- Имя хранения случайное; исходное имя не используется как путь.
- Чужой `file_id` нельзя прикрепить к своей работе.
- Неодобренный файл не доступен гостю.
- Временная ошибка загрузки оставляет форму с понятным сообщением и позволяет повторить действие.
- Потеря сети не должна создавать повторные работы или сообщения после повторного нажатия.

## Повторный запуск и обновление

### Перезапуск без потери данных

```bash
docker compose down
docker compose up -d
```

После запуска проверьте `/api/health`, ранее созданную работу, чат и сохранённый файл. Не используйте `down -v` в production.

### Резервная копия перед обновлением

Сохранять нужно согласованную пару:

- SQLite-файл вместе с `-wal`/`-shm`, либо SQLite backup, выполненный штатным механизмом;
- весь каталог uploads.

После резервного копирования:

1. собрать новую версию;
2. запустить контейнеры;
3. проверить health;
4. открыть приложение гостем и одной реальной ролью;
5. проверить чтение старого файла;
6. проверить запись новой работы;
7. только затем завершить окно обновления.

## Production acceptance checklist

| Проверка | Ожидаемый результат |
| --- | --- |
| HTTPS и сертификат | без предупреждений браузера |
| открытие из MAX | init data присутствуют, сессия загружается |
| `X-Max-User-Id` без init data | `401` |
| неверная/устаревшая подпись | `401` |
| гостевой портфель | работает без авторизации, приватных полей нет |
| ученик → преподаватель → ученик | работа, проверка, уведомление и доработка проходят |
| чат | только назначенные пары, чужой диалог даёт `403` |
| файл | сохраняется после перезапуска и защищён по ролям |
| admin API от ученика/преподавателя | `403` |
| перезапуск Compose | БД и uploads сохраняются |
| demo UI в production | переключателя ролей нет |

## Что проверяется автоматически, а что вручную

Автоматически выполняются unit-тесты MAX-подписи, разграничения чата и файлов, а `testing/api-smoke.mjs` проверяет временную БД, роли, регистрацию, гостевую приватность, двусторонний чат и полный цикл реального PNG-файла.

Вручную на опубликованном стенде обязательно проверяются карточка бота, мобильный клиент MAX, реальная подпись, TLS, safe-area, системная тема, медленная/пропавшая сеть и сохранение production-volume после обновления.
