# Архитектура MADCAP Barber Academy

Новая версия разделена на два самостоятельных приложения:

```text
backend/   NestJS + TypeScript + SQLite
frontend/  React + TypeScript + Vite
```

## Backend

- `auth/` — проверка подписанных MAX init data и контекст текущего пользователя;
- `database/` — подключение SQLite, схема и миграции;
- `users/` — внутренняя учётная запись, роли и session endpoint;
- доменные модули (`students`, `teachers`, `homeworks`, `chat`, `notifications`, `guest`, `admin`) не смешивают HTTP-слой и SQL-запросы;
- контроллеры отвечают за HTTP и DTO, сервисы — за сценарии, repositories — за SQL.

Публичный API использует внутренний `users.id` для связей, а MAX ID только как внешнюю идентичность. До добавления других платформ текущая MAX-only схема хранит его в `users.max_user_id`; переход на `user_identities` будет отдельной миграцией.

## Frontend

- `platform/` — MAX Bridge и запуск приложения;
- `api/` — типизированный HTTP-клиент;
- `features/auth/` — загрузка сессии и guard-контекст;
- `pages/` — страницы сценариев;
- `components/` — переиспользуемые визуальные компоненты и layout;
- `styles/` — глобальные токены и стили.

Каждая новая страница должна получать данные через API-клиент и не обращаться к SQLite, `window.WebApp` или `fetch` напрямую.

## Сохранение поведения

Рефакторинг не меняет предметную модель: роли ученика, преподавателя, администратора и гостя, домашние задания, проверки, комментарии, уведомления, чаты, портфолио, конфиденциальные отзывы и профильные заявки должны сохранять прежние сценарии и права доступа.
