## Зафиксированные решения

### 2026-09-17 — Приложение работает только в MAX

- **Контекст:** прежние платформенные интеграции больше не нужны, а production-сервер и ценная production-база пока отсутствуют.
- **Решение:** оставить единственной платформой MAX, хранить идентификатор аккаунта напрямую в `users.max_user_id` и проверять подписанные MAX init data. Для локальной разработки сохранить отдельный браузерный режим без платформенной авторизации.
- **Причина:** единая модель платформы уменьшает сложность авторизации, конфигурации и сопровождения.
- **Последствия:** прежняя локальная SQLite-база несовместима с новой схемой и должна быть создана заново. Старые платформенные клиенты, вход через браузерные токены и внешние уведомления удалены; внутренние уведомления приложения сохранены.

### 2026-09-14 — Роли, уровни обучения и публичная витрина

- **Контекст:** нужен единый сайт с разными правами и наглядным разделением пути ученика.
- **Решение:** ученики, преподаватели и администраторы входят только через MAX; гость открывает публичную витрину по ссылке без авторизации. Учеников разделяют уровни «Ученик», «Стажёр», «Барбер».
- **Причина:** это отделяет публичное портфолио от учебных данных и облегчает навигацию в больших списках.
- **Последствия:** контакты, никнеймы и служебные идентификаторы не передаются гостю. Администратор назначает уровень; при уровне «Барбер» все привязки к преподавателям автоматически снимаются. При возврате в обучение преподавателя назначают заново.

### 2026-09-14 — Конфиденциальная обратная связь ученика

- **Контекст:** ученику нужен безопасный канал для пожеланий о преподавателе и академии.
- **Решение:** отзыв отправляется отдельной формой и доступен только ученику при отправке и администраторам при просмотре. После принятия уроков 5, 10 и 15 приложение показывает ученику внутреннее приглашение оставить отзыв.
- **Причина:** преподаватель не должен получать текст или уведомление об отзыве, чтобы ученик мог говорить открыто.
- **Последствия:** отзывы не являются анонимными для администратора: он видит автора. Таблицы `private_feedback` и `feedback_milestones` не использовать как часть чатов или портфолио.

### 2026-09-07 — Локальный браузерный предпросмотр без платформы

- **Контекст:** основной интерфейс блокирует обычный браузер, потому что ждёт запуск из MAX.
- **Решение:** отдельная local Compose-конфигурация собирает frontend с `VITE_DEMO_MODE=true`, запускает API с `MAX_WEBAPP_AUTH=off` и показывает безопасный переключатель трёх обезличенных demo-ролей.
- **Причина:** это позволяет посмотреть интерфейс локально, не подставляя реальные аккаунты и не меняя production-авторизацию.
- **Последствия:** режим доступен только в development/local Compose; production-сборка работает со строгой MAX-подписью и не принимает demo-заголовок.

### 2026-09-06 — Постоянная память проекта хранится в репозитории

- **Контекст:** нужно сохранять важный контекст между задачами, не перечитывая весь код.
- **Решение:** использовать `PROJECT_CONTEXT.md`, этот журнал, `WORK_LOG.md`, `QUALITY_RULES.md` и правила в `AGENTS.md`.
- **Причина:** документы доступны при следующей задаче, проверяемы и обновляются вместе с проектом.
- **Последствия:** существенные решения и завершённые задачи необходимо кратко фиксировать в подходящем документе.
