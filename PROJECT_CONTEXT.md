# Контекст проекта MADCAP Barber Academy

## Назначение

MAX Mini App для ведения обучения в барбер-академии. Ученик сдаёт работы и
получает обратную связь, преподаватель ведёт назначенных учеников,
администратор управляет академией, а гость видит безопасное публичное
портфолио.

Поддерживается только MAX. Telegram, VK и отдельный web-login не входят в
целевой продукт.

## Активный стек

- frontend: React, TypeScript, Vite;
- backend: NestJS, TypeScript;
- данные: SQLite и файловое хранилище uploads;
- runtime: Node.js 20;
- локальный/production запуск: Docker Compose, Nginx;
- авторизация: подписанные MAX init data в строгом режиме.

## Активная структура

| Путь | Назначение |
| --- | --- |
| `frontend/src/` | страницы ролей, компоненты, темы, MAX bridge и API client |
| `backend/src/` | Nest-модули авторизации, ролей, работ, файлов, чата и администрирования |
| `backend/scripts/` | проверка MAX-токена и идемпотентный demo seed |
| `testing/api-smoke.mjs` | сквозная проверка на временной БД и временных uploads |
| `docker/`, `Dockerfile.*`, `docker-compose*.yml` | воспроизводимый запуск frontend/API/SQLite |
| `docs/` | архитектура, сценарии, аудит, запуск и сдача |

Корневые `src/`, `bot/` и `files_new/` оставлены как исторические материалы
миграции и не участвуют в активной сборке. Новую функциональность следует
реализовывать только в `frontend/` и `backend/`.

## Роли и границы доступа

- Гость: активные публичные ученики и только одобренные работы, без контактов,
  MAX ID, username, приватных комментариев, чата и обратной связи.
- Пользователь без роли: onboarding ученика или заявка преподавателя.
- Ученик: собственный профиль, работы, файлы, доработки, комментарии,
  уведомления и чат только с назначенными преподавателями.
- Преподаватель: только назначенные ученики, их работы и защищённые файлы;
  оценка 1–5, отзыв, доработка, комментарии и чат.
- Администратор: пользователи, роли, назначения, модерация, обратная связь,
  работы и журнал действий.

MAX ID используется для установления внешней личности. Все внутренние связи
строятся через `users.id` и доменные первичные ключи.

## Данные

Production SQLite и uploads должны находиться на постоянном volume и
резервироваться вместе. Файл БД, WAL/SHM, uploads, backups и `.env` не
коммитятся.

Demo seed:

- не очищает существующую БД;
- безопасно запускается повторно;
- создаёт обезличенные роли, связи, все основные статусы работ, изображения,
  чат, уведомления, заявки, обратную связь и audit;
- сохраняет действия эксперта между обычными перезапусками Compose.

## Проверка готовности

Источники приёмки:

- `docs/PRODUCT_AUDIT.md`;
- `docs/DEMO_SCENARIOS.md`;
- `docs/PRODUCTION_USER_SCENARIOS.md`;
- `docs/FUNCTIONAL_PARITY.md`.

Основной прогон:

```bash
npm ci
npm test
npm run lint
npm run build
npm run test:smoke
docker compose -f docker-compose.yml -f docker-compose.local.yml config --quiet
```

Для релиза дополнительно требуется фактический Docker build/up, health-check и
ручная проверка опубликованного HTTPS Mini App внутри мобильного MAX.

## Ограничения управления

Автоматический deployment отключён. Push, deploy, изменение Git-истории,
настройка внешней инфраструктуры и миграция ценной production-БД выполняются
только после отдельного разрешения.
